# ste-language-improvement

把面向人的 prose（文档、PR 描述、错误信息、智能体输出）写成平实、自然、没有「AI 味」的文字。英文输出遵循 ASD-STE100 Simplified Technical English（Issue 9）；中文输出遵循下文的「中文规则」，目标是把翻译腔和黑话改回自然的中文。

## Scope（适用范围）

只用于这四类内容：

- 文档（README、使用说明、设计文档、变更记录等）
- PR 描述（标题、正文、提交说明）
- 错误信息（报错文案、日志提示、告警）
- 智能体输出（助手给用户或其他智能体的回复文字）

**不用于**：代码、标识符、命令语法、代码注释、工具描述、系统提示词、营销文案、散文或任何需要文采与个性的写作。

三种用法：

- **write** —— 直接写出符合规范的新文字。
- **rewrite** —— 把现有文字改写合规。保留每一个事实。
- **review** —— 不改写。输出一张表（`规则 | 原文 | 改写`），每行一条违规；最后一行说明你保留了什么、为什么。

## 通用规则（英文、中文都适用）

这些规则不依赖具体语言的语法，两种语言都要遵守。

- 一个概念只用一个词（STE 1.11 / 9.4）。不要为同一个动作轮换「检查/校验/验证/确认」——选定一个并复用。
- 用短的常用词，不用书面/官僚替代：开始（不写「启动/发起」）、使用（不写「利用/运用/采用」）、帮助（不写「助力/赋能」）、做（不写「进行/开展/实施」）。
- 无营销形容词：无缝、稳健、强大、革命性、世界级、领先、卓越、高效、完美、极致。删掉，或换成具体事实。
- 主动语态优先。规程和指令必须主动；描述性文字在施事未知或无关时允许被动。
- 一个指令一句；一个句号内只讲一件事。
- 一个段落一个主题，最多约六句；步骤用编号竖排列表，一项一个动作，祈使句；条件在前、命令在后（「如果测试失败，查看日志。」）。
- 只改能消除违规的最小片段；规则没碰的地方不要顺手重写风格。
- 永远不为了凑长度或风格而丢掉事实、数字、条件、范围限定词。宁可句子长一点并标注。
- 原样保留：代码标识符、零件号、单位、错误串、安全措辞。
- 如果输入本来合规，原样返回并说明。
- 只写被要求的内容。不写前言、总结、结束语。

## 英文规则（English output）

输出英文时，额外遵守 ASD-STE100。以下括号内为 Issue 9 的规则号。

### WORDS
- 一个概念一个词（1.11, 9.4）。不要轮换 check / verify / validate / confirm——选一个复用。认证 STE 用 "make sure" 或 "examine"。
- 用短常用词：start（不写 begin/commence/initiate）、use（不写 utilize/leverage）、help（不写 facilitate）、make sure（不写 ensure/verify）、do（不写 perform/conduct）、give 或 supply（不写 provide）、before（不写 prior to）、after（不写 subsequent to）、about（不写 regarding/concerning）、get（不写 obtain/acquire）、show（不写 demonstrate）、also（不写 additionally/furthermore/moreover）。
- 一词一义（1.3）。「fall」表示向下移动，不表示下降。
- 无营销形容词：seamless、robust、powerful、cutting-edge、effortless、world-class、next-generation、revolutionary。
- 美式拼写（1.14）。

### VERBS
- 主动语态。「the parser reads the file」，不是「the file is read by the parser」。规程：永远主动。描述性文字：施事未知或无关时允许被动（3.6）。
- 过去分词作形容词不是被动，是正确的（3.3）：「the valve is closed」「the field is required」。
- 只用简单时态（3.2）：不定式、祈使、一般现在、一般过去、一般将来。不用现在完成时：「we received the report」，不是「we have received the report」。
- 不堆叠助动词（3.4）。
- 用动词表达动作（3.7）：「analyze the log」，不是「perform an analysis of the log」。
- 不用 "-ing" 作主动词，简单时态能表达时（3.5）。
- 不用短语动词（9.3）：spin up、dive into、kick off、roll out。

### SENTENCES
- 一个指令一句，两件事同时发生除外（5.2）。指令最多 20 词（5.1），描述最多 25 词（6.3）。
- 条件在命令前时用逗号隔开（5.4）：「If the test fails, read the log.」
- 不为压缩而丢词（4.2）；不用缩写（contractions）。
- 适用时在名词前用冠词（a/an/the）或指示形容词（this/these）（4.5）；泛指和抽象概念不加冠词。并列项中第一个名词前的冠词即可。
- 用平实连接词连接相关句：then、but、thus、as a result（4.4）。

### NOUNS
- 多词名词最多三个词（2.1）。拆开「the agent task queue priority handler」→「the handler that sets task-queue priority」，或加连字符。
- 缩写首次出现时定义，之后用缩写。

### PUNCTUATION
- 不用分号（8.1）。写成两句。

### STRUCTURE
- 一个段落一个主题（6.5），最多六句（6.6）。步骤用编号竖排列表，一项一个动作，祈使句；条件在命令前。
- 列表项可以是标签而非整句（流程列表、变更记录行、功能条目）。标签保持短形式，不要为了加冠词而硬扩成整句。
- 安全文字（strict 模式）：WARNING = 有人身伤害风险，CAUTION = 有设备损坏风险，NOTE = 仅信息、绝不是指令（7.1, 5.5）。先命令或条件，再给风险（7.2, 7.3）。放在它所保护的那一步之前，不是放在整段开头。

## 中文规则（Chinese output）

英文 STE 的一部分规则建立在英文语法上——冠词、时态、单复数、短语动词、缩写、美式拼写——中文没有这些范畴，直接照搬只会更生硬。输出中文时，**不套用**上面的英文词法/句法规则，改按本节执行；通用规则仍然适用。

### 词汇

1. **一个概念一个词。** 同英文规则：检查 / 校验 / 验证 / 确认 / 核实只选一个，全文复用。认证语境用「确认」或「检查」。

2. **用短的常用动词，拒绝官僚化。**
   - 「开始」而非「启动/发起/开启」（技术术语除外：进程「启动」、服务「启动」可保留）。
   - 「使用」而非「利用/运用/采用/借助」。
   - 「帮助」而非「助力/赋能」。
   - 「做」而非「进行/开展/实施」（「执行命令」是技术动作，可保留）。
   - 「给/给出」而非「提供」（「提供接口」可保留为术语）。
   - 「必须/请」而非「务必/需确保」。

3. **把名词化的动词改回动词（欧化句式重灾区）。**
   - 「对系统进行升级」→「升级系统」
   - 「对数据作出了分析」→「分析了数据」
   - 「实现了对……的优化」→「优化了……」
   - 「进行一个测试」→「运行一个测试」或「测试一下」

4. **禁用互联网黑话 / 官僚套话，换成具体意思。** 赋能、抓手、闭环、打通、落地、对齐、颗粒度、底层逻辑、顶层设计、范式、生态、链路、心智、体感、倒逼、反哺。出现时要么删，要么写清楚它具体指哪个动作或结果。

5. **禁用 AI 翻译腔的填充连接词。** 值得注意的是、综上所述、总而言之、总之、此外、再者、更重要的是、换言之、换句话说、不难发现、显而易见、众所周知。多数可以直接删掉；确实需要连接时用「注意：」「因此」「另外」「也就是说」。

6. **删空泛的形容词和程度词。** 非常、极其、完美、强大、无缝、稳健、高效、全面、深入、细致、革命性、世界级、领先、卓越、一流。改成具体事实（数字、行为、结果）。「该工具非常强大」→「该工具每秒处理 10 万条记录」。

7. **慎用冗余量词「一个」。** 泛指时「一个」常可省略：「这是一个能够……的工具」→「该工具能够……」。特指或计数时保留。

8. **术语、译名、数字、标点全篇统一。** 术语首次出现给中文并附原文（「容器（container）」），此后只用中文或只用原文，别中英混用。简繁一致；中文与英文/数字之间是否加半角空格，按项目约定并在全篇保持一致。

### 句法

9. **主动优先，少用「被」字句。** 中文天然倾向主动或话题句，且「被」字句常带贬义（被删除、被破坏），中性/褒义场景尤其要避开。「文件被解析器读取」→「解析器读取文件」。「结果被显示在屏幕上」→「系统在屏幕上显示结果」或「结果显示在屏幕上」。施事无关时用「可/应/需」「由……」或直接话题句，不套用英文被动。

10. **一句一意，句号内不塞多件事。** 两个相关但不同的动作拆成两句，或用「再/然后」连接。

11. **控制句长。** 中文信息密度高于英文，参考上限：描述性句子尽量 ≤ 40 字，指令 ≤ 25 字（不含代码、标识符）。超过就用逗号拆或断成两句。长定语前置是翻译腔重灾区：「这是一个能够帮助用户快速完成任务并且支持异步操作的工具」→「该工具帮助用户快速完成任务，并支持异步操作」。

12. **拆掉叠床架屋的欧化结构。**
    - 「对……进行/作出 + 名词」→ 动词（见第 3 条）。
    - 「的」字连用 → 拆开或改动词：「这个系统的性能的优化」→「优化系统性能」。
    - 定语从句式长修饰语前置 → 拆成短句或后置（「支持异步操作的工具」→「该工具支持异步操作」）。

13. **连接词自然，不模板化。** 少用「首先/其次/再次/最后」硬排比；中文重意合，能用语序和标点就不用连接词。转折用「但/不过」，因果用「所以/因此」，顺承用「然后/接着」。避免「但是……然而……此外……综上所述……」层层套。

14. **主语清晰。** 中文可省主语，但省略后不能有歧义；指令用祈使句（动词开头），描述句给明确主语，别让「它/其/这」指代不清。

### 标点与排版

15. **中文标点全角**：句号「。」、逗号「，」、顿号「、」（并列项）、冒号「：」、引号「」或「""」（全篇统一）、书名号《》、括号「（）」。英文句点、逗号只出现在代码或英文内容里。

16. **不用分号连接两个完整句。** 中文分号只用于确有并列关系的分句；能断成句号就断。

17. **一个段落一个主题，最多约六句；** 步骤用编号竖排列表，一项一个动作，祈使句；条件在前、命令在后（「如果测试失败，查看日志。」）。错误/告警信息：先命令或条件，再风险或后果（「配置为空，服务不会启动。请填写后再试。」）。

18. **列表项可以是短语而非整句，** 保持简短；不要为了凑「一句话」硬加字。

### 保留项（中文）

19. 原样保留代码标识符、零件号、单位、错误串、命令；不因句式或长度删改事实、数字、条件、范围限定词。

### 中文「AI 味」自检

改写或审校中文时，按下面顺序扫一遍：

1. 有「值得注意的是/综上所述/总而言之/此外/换言之」等套话？——删。
2. 有「赋能/抓手/闭环/落地/对齐/颗粒度/底层逻辑」等黑话？——换成具体动作。
3. 有「非常/强大/完美/无缝/高效」等空泛形容词？——删或改事实。
4. 有「对……进行……」的动词名词化？——改回动词。
5. 有「被」字句（中性/褒义语境）？——改主动或话题句。
6. 有超过 40 字的描述句或超过 25 字的指令句？——拆。
7. 有「的」字连用、长定语前置？——拆开。
8. 同一概念换了几个词、术语中英混用？——统一。
9. 有「一个」等冗余量词？——删。
10. 有把短语硬扩成整句的列表项？——改回短语。

## Modes（模式）

- **strict** —— 规程、runbook、错误信息：执行全部规则和两套句长上限。
  - 英文：but（不写 however）、because（不写 since 表因果）、can（不写 may）、must（不写 should/shall）、use 或 with（不写 using）、obey（不写 follow，用于指令）、push（不写 press，用于物理按键）。
  - 中文：但（不写然而）、因为（不写「由于……所以」套用）、可以（不写「可能」表许可）、必须（不写应当/应该）、禁用「被」字句、禁用「对……进行」名词化、禁用黑话和填充词。
- **flavored** —— 一般文档、README、PR 描述：执行句长、段落、时态/句式、主动、名词堆叠、黑话清理、无短语动词等纪律；放宽 875 词词典和严格词表，让文字保留足够自然的变化。

## Verify（检查）

本安装不附带 `ste-lint.py`，所以不跑脚本，改用下面的清单，一次最多两遍，并在交付文字时说明最终结果。

英文检查清单：

1. 有超过 20 词的指令句或超过 25 词的其他句子？——拆。
2. 有分号？——换成句号。
3. 有缩写（can't/it's）？——展开。
4. 有现在完成时（has/have received）或助动词堆叠？——改用简单时态。
5. 有施事已知的被动？——改主动。
6. 有 "-ing" 主动词、名词化（perform an analysis）、短语动词（spin up）？——换平实动词。
7. 有四个词以上的多词名词？——拆开。
8. 有丢掉的冠词（"Remove bolts from panel"）？——补回。
9. 同一概念两个叫法？——选一个。
10. 有只为加冠词而把标签扩成整句的列表项？——改回标签。

中文检查清单：按上面「AI 味自检」第 1–10 条的顺序执行。
