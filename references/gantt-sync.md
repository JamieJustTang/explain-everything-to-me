# 甘特图同步

这项功能只在用户显式调用 `explain-everything-to-me` 后运行。页面与 Skill 共用本机 `~/.explain-everything-to-me/gantt/data.json`。页面可以手动新建多张图、项目和任务，并修改项目 DDL。只有开启“Agent 自动同步”的图表会接收自动更新。数据文件留在本机，不进入 Skill 仓库。

## 每次调用后的动作

1. 完成当前请求所需的检索、原文阅读和事实判断。不要为了填满甘特图扩大搜索范围。
2. 运行 `python3 <SKILL_DIR>/scripts/gantt.py show`，只在**本次已经读过并核对**的证据中，找与现有图表项目 `workspace` 精确匹配的工作。工作区路径不确定时跳过。不要根据文件夹名字相似就合并项目。
3. 为实际改变任务状态或计划的证据生成事件。`key` 是该项目内稳定的任务键，例如 `aamas-manuscript`；重复调用同一键只更新原任务。状态 `planned|active|blocked|done`，进度百分比只有证据中明确给出时才写。日期只填用户明确指定或可靠来源明确给出的日期；不要把报告时间当任务截止日，也不要根据时间线自动推算。`workrefs` 至少一条已打开的 sivtr WorkRef。事件的 `observed_at` 是带时区的证据时间，不是同步时间。备注只写与任务状态有关的简短结论，不复制密钥、个人敏感内容或整段会话。
4. 将 JSON 写到本机临时文件，再运行 `python3 <SKILL_DIR>/scripts/gantt.py sync --input /path/to/events.json`。完成后删除临时文件。也可以把 JSON 通过标准输入传给 `--input -`。即使本次没有可同步事件，也传 `{"events":[]}`，记录本次同步检查时间。脚本返回新增、更新、跳过和未映射的数量；同步失败时继续回答用户，末尾简短说明。
5. 对有多张图的用户，默认同步到所有开启自动同步且包含精确匹配工作区的图。事件可带 `chart_id` 限定一张图。未映射项目不会自动插入，避免把无关项目塞入用户自己分类的图。用户可以在页面新建项目并填工作区路径，再让后续调用同步。

## 事件格式

```json
{
  "events": [
    {
      "workspace": "/实际/工作区/绝对路径",
      "key": "study2-pilot",
      "title": "核对 M3 pilot 统计口径",
      "status": "done",
      "notes": "重算后已更正失败率；正式实验准入仍待定。",
      "workrefs": ["codex/例子/1"],
      "observed_at": "2026-09-28T12:54:52+08:00"
    }
  ]
}
```

例子只展示结构，运行时必须替换为本次读过的真实证据。所有事件有 `workspace`、`key`、`title` 和 `workrefs`。首次创建任务可加 `start`、`due`、`progress`；日期格式 `YYYY-MM-DD`。后续事件只更新显式给出的字段；手动改过的任务字段不会自动覆盖。页面里删除自动任务后，同一 `key` 不会再次创建。项目级 DDL 始终由用户在页面维护；Skill 不自动改写。

## 启动页面

```bash
python3 <SKILL_DIR>/scripts/gantt.py serve
```

浏览器打开 `http://127.0.0.1:8765/`。服务只监听本机回环地址，依赖 Python 标准库。不同宿主的安装副本都读写同一份用户数据。不要自动启动长期后台服务；用户需要页面时再启动。
