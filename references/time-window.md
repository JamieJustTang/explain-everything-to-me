# “最近”的时间范围

每次调用先读取本次和本会话上一次显式调用的用户消息时间。若本次用户消息没有可读时间戳，立即读取当前系统时间并标明是“开始处理时间”的近似值。时区以用户或宿主会话时区为准；查询 sivtr 时转为它接受的 RFC3339 时间。若上次调用与本次调用在同一秒，用空区间处理，不向前硬扩。

上下文不完整时，可先用 `sivtr s agent -m "explain-everything-to-me" --latest 20 -f timeline` 查命令记录，再从 ref 和宿主会话信息中核对是否属于**当前同一 session**；当前命令本身不是“上一次”。如果 sivtr 尚未同步到该 session，改用宿主的只读会话历史。不能仅凭同工作区、同 Agent 或时间邻近就认定是同一会话。

判断顺序：

1. 用户给出明确起止时间、日期或“过去 N 天”，直接使用；不要被上次调用覆盖。
2. 用户说“最近”“这段时间”“自上次解释以来”，或只输入命令：上次**同一宿主会话**调用时间可靠时，以它为起点，以本次调用时间为终点。即使上次只问了某个项目，本次默认范围也从那次调用起；搜索主题仍由本次请求决定。
3. 首次调用或找不到可靠上次时间时，无参数请求先探查过去 3 天；若用户给了主题却说“最近”，可按该主题的活动密度合理缩放，并明确报告范围。
4. 证据冲突时优先用户消息的时间戳，其次同一 session 的 sivtr 记录；上次回答中的时间标记只能作为回溯线索。仅凭另一会话的调用或猜测的时间，不可建立起点。

以下情况要弹出选项：本会话存在多个可能的上次调用且无法辨认；记录只有日期没有时刻而小时级差异会影响答案；用户同时写“最近”和互相矛盾的日期；缺失上次调用且 24 小时与 3 天会给出明显不同的结论。可用选项 UI 时给互斥选择：

- “自上次调用起”（只在时间可靠时提供，推荐）
- “过去 24 小时”
- “过去 3 天”

若上次调用时间不可靠，改为“过去 24 小时 / 过去 3 天（推荐）/ 自选起止时间”。宿主没有选择 UI 时列出同样的编号选项，等待用户回复后再进行依赖时间段的检索。不能把等待超时当作用户选择。

完成后在回答中写明实际起止时间、时区和范围来源，并记录本次**调用**时间供下一次使用。先前回答漏写标记时，仍应尝试从会话原始记录找回。

增量请求中的“新”由**事件时间**判定，不由“上次是否汇报过”判定。例如上次只解释 Harbor、本次问各工作区“又发生了什么”，而 Orchid 记录早于上次调用，则 Orchid 不算新进展。可补充为明确标注的旧背景，但主结论应是“该区间无新增记录”。
