# 按工作区详读模板

适合用户点名项目、要求复盘原因，或明确要求详细版本。按问题调整顺序和深度；不要机械填满所有栏目。

## 当前结论

先用平实语言说明用户要解决的问题、这些工作区各自承担什么角色，再回答“现在到哪一步”。区分通过、未通过、尚未验证；从记录推断的目标要标明。涉及多个工作区时，先给一段跨项目概览。

## 每个相关工作区

对每个工作区依次说明：

1. 这里服务哪个用户目标；本次活动属于探索、实现、验证、修正结论还是其他实际工作性质。不要把工作区名直接当目标。
2. 已完成的关键工作，以及可核对的验证结果。
3. 相比之前改变了什么判断，为什么改变。
4. 仍未解决的阻塞、风险或证据缺口。
5. 下一步由 Agent 继续做什么；只有真正需要用户选择时才写用户待决项。

把同一目标跨工作区的关系说清；一个工作区里有多个不相干目标时分开说明。把同一任务的多个 session 合并成一条因果线，不按消息时间逐条复述。保留关键数字，解释其含义；不要倾倒方法哈希、文件路径、矩阵格数或测试清单。每个重要判断就近附少量 WorkRef；若当前文件状态也经过验证，和历史会话证据分开写。

## 范围与限制

末尾写实际时间范围、来源、重要缺口，以及 Skill 规定的时间标记。默认不单列检索过程或“我读了多少条”，除非这会改变用户对覆盖程度的判断。
