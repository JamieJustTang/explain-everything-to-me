# 按工作区详读模板

适合用户点名项目、要求复盘原因，或明确要求详细版本。按问题调整顺序和深度；不要机械填满所有栏目。

## 当前结论

先回答“现在到哪一步”，说明通过、未通过、尚未验证的界限。涉及多个工作区时先给一段跨项目概览。

## 每个相关工作区

对每个工作区依次说明：

1. 已完成的关键工作，以及可核对的验证结果。
2. 相比之前改变了什么判断，为什么改变。
3. 仍未解决的阻塞、风险或证据缺口。
4. 下一步由 Agent 继续做什么；只有真正需要用户选择时才写用户待决项。

把同一任务的多个 session 合并成一条因果线，不按消息时间逐条复述。保留关键数字，解释其含义；不要倾倒方法哈希、文件路径、矩阵格数或测试清单。每个重要判断就近附少量 WorkRef；若当前文件状态也经过验证，和历史会话证据分开写。

## 范围与限制

末尾写实际时间范围、来源、重要缺口，以及 Skill 规定的时间标记。默认不单列检索过程或“我读了多少条”，除非这会改变用户对覆盖程度的判断。
